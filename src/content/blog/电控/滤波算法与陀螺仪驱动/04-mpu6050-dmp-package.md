本篇只解读 `6050-正点原子DMP库.zip`。包内同时存在底层寄存器驱动、InvenSense Motion Driver、DMP 映射表和自定义 `IMU.c`，但“包含 DMP 文件”不等于“当前输出已经走 DMP”。

## 代码包由哪些层组成

| 层次 | 代表文件 | 作用 |
| --- | --- | --- |
| 板级适配 | `board.c/.h` | MSPM0 DriverLib 与 I²C 适配 |
| 寄存器驱动 | `bsp_mpu6050.c/.h` | 配置、收发、原始六轴读取 |
| DMP 上游 | `inv_mpu.c/.h` | MPU 配置、FIFO 与传感器接口 |
| DMP Motion Driver | `inv_mpu_dmp_motion_driver.c/.h` | 固件、特征、四元数接口 |
| 应用融合 | `IMU.c/.h` | 读取六轴并生成 Roll 等变量 |

文件存在只能证明代码随包分发。是否参与构建、是否被调用，必须从实际入口追踪。

## MPU6050 底层初始化

`bsp_mpu6050.c` 通过 I²C 写寄存器完成复位、时钟源、量程、低通和采样相关配置，并提供寄存器读写与多字节读取。

初始化流程还应核对 `WHO_AM_I` 和每一步返回值。资料中的返回值注释与实现语义存在冲突，调用者可能把失败当成功。

代码引用了压缩包中不存在的 `bsp_system.h`。这意味着包不是自包含工程，移植时需要明确补齐时间、延时或系统接口，不能临时编造同名函数。

## I²C 状态机与超时

底层通过 MSPM0 DriverLib 和中断状态维护收发过程，但多个等待循环没有超时。

若设备缺失、地址错误、总线被拉低或中断未到达，函数可能永远不返回。放进协作式调度器后，一次 I²C 故障会冻结所有周期任务。

工程化接口至少应返回 `OK / TIMEOUT / NACK / BUS_ERROR`，并在截止时间后停止传输、恢复总线状态。上层收到错误后必须使姿态数据失效，而不是继续使用旧值。

## DMP 文件是否真正启用

包内有 `dmp_load_motion_driver_firmware()`、FIFO 和四元数相关接口，也有大量 DMP 映射表。

但当前 `IMU_getEuleranAngles()` 没有调用 `dmp_read_fifo()`，也没有从 DMP FIFO 获取四元数。可达路径读取原始加速度和角速度，再计算自定义 Roll。

因此证据状态是：DMP 源文件存在；当前 `IMU.c` 输出链未确认使用 DMP。文章不会把它描述为“已经运行 DMP 姿态融合”。

## 当前 Roll 输出链

`IMU.c` 由加速度向量计算横滚角，再用 X 轴陀螺仪积分，最后通过互补滤波融合：

```text
加速度 XYZ → 几何 Roll ─┐
陀螺仪 X → 积分 Roll ───┼→ 互补滤波 → 最终 Roll
```

这条路径轻量，但车辆存在明显线加速度时，加速度计不再只测重力，几何角会受到干扰。滤波权重和调用周期必须用动态日志验证。

## `fast_sqrt()` 的数学错误

函数先用经典位级近似得到约等于 `1/sqrt(x)` 的值，最后却返回：

```c
return 1.0f / conv.f * x;
```

若 `conv.f ≈ 1/sqrt(x)`，该式约等于 `x·sqrt(x)`，不是 `sqrt(x)`。它会破坏向量或四元数归一化。

修复前应先用 `x=1、4、9` 等已知输入建立测试，再选择标准 `sqrtf()` 或经过验证的快速平方根实现。不能只看姿态曲线“似乎还能动”。

## 角速度单位问题

代码把陀螺仪换算成度每秒，又把值送入四元数微分相关计算。常见四元数微分公式要求弧度每秒；若不转换，积分尺度会错误。

更关键的是，这部分四元数结果没有进入最终 Roll 返回链。它目前属于实验代码，不是主输出的依据。

## 推荐移植步骤

1. 先补齐缺失依赖并让底层驱动可独立构建。
2. 为每个 I²C 等待加入超时和错误返回。
3. 读取 `WHO_AM_I`，记录原始六轴和时间戳。
4. 修复并测试平方根、单位和归一化。
5. 在“原始六轴互补滤波”和“DMP FIFO”两条路径中明确选择一条。
6. 若启用 DMP，增加 FIFO 溢出、包长度和新鲜度处理。

## 证据边界

| 结论 | 状态 | 依据 |
| --- | --- | --- |
| 包含 MPU6050 与 DMP 上游源码 | 仅发现文件 | 压缩包内容 |
| 当前 `IMU.c` 使用 DMP FIFO 输出 | 否 | 无 `dmp_read_fifo()` 可达调用 |
| 当前 Roll 使用原始六轴互补滤波 | 已由代码确认 | `IMU_getEuleranAngles()` |
| I²C 故障可超时恢复 | 否 | 等待循环无截止条件 |
| 代码包可直接构建 | 否 | 缺少 `bsp_system.h` 等依赖 |

## 本篇总结

- 代码包同时包含底层驱动、DMP 上游和自定义融合，三者不能混为一条已启用链路。
- 当前可确认的 Roll 输出来自原始六轴互补滤波，不是 DMP FIFO。
- `fast_sqrt()`、角速度单位和初始化返回语义存在明确风险。
- 无超时 I²C 会阻塞整个非抢占式系统。
- 移植时应先建立可靠底层和错误路径，再决定使用 DMP 还是自定义融合。
