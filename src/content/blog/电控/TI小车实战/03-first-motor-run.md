硬件调试的第一目标不是“让所有模块同时工作”，而是证明每个电源域、接口和保护边界都清楚。只有先建立安全基线，后面的控制现象才有解释价值。

## 1. 电源域不是一个“VCC”

当前系统涉及驱动电源、5 V、3.3 V 和舵机 7 V。扩展板把驱动电源送给 TB6612 的 `VM`，5 V 供给逻辑与部分模块，系统板再由 5 V 生成 3.3 V 供 MCU 使用。

| 电源域 | 主要负载 | 首次检查 |
| --- | --- | --- |
| 驱动电源 | TB6612 与直流电机 | 极性、空载电压、启动压降 |
| 5 V | 系统板输入、编码器及模块接口 | 是否与调试器供电形成反灌 |
| 3.3 V | MSPM0G35XX 与数字逻辑 | 稳态电压、复位时跌落 |
| 7 V | 舵机接口 | 本专题默认先断开 |

“模块用 5 V 供电”不代表它输出给 MCU 的信号就是 3.3 V。编码器、OLED 或传感器的输出类型必须查资料或实测，不能用经验替代电平确认。

## 2. 当前电机接口基线

| 功能 | MCU 引脚 / 外设 | 连接对象 |
| --- | --- | --- |
| 左轮 PWM | PB14 / TIMA0 C0 | TB6612 PWMA |
| 左轮方向 | PB5、PB10 | AIN1、AIN2 |
| 右轮 PWM | PA7 / TIMA0 C1 | TB6612 PWMB |
| 右轮方向 | PB7、PB6 | BIN1、BIN2 |
| 驱动待机 | PB8 | STBY |
| 左编码器 | PB15、PB11 / TIMG8 | QEI A/B 相 |
| 右编码器 | PA3、PB9 / TIMG9 | QEI A/B 相 |

这张表同时受到 PCB 版本和实物排线影响。源码与 SysConfig 能证明 MCU 侧配置，不能单独证明连接器方向。插接前仍要以实物丝印、原理图针号和通断测量确认。

## 3. 其他当前接口

| 功能 | 引脚 | 当前软件状态 |
| --- | --- | --- |
| OLED | PA31 SCL、PA28 SDA | 初始化成功后显示 |
| IMU 总线 | PA29 SCL、PA30 SDA，PA10 INT | 驱动保留，默认关闭 |
| 调试 UART | PB3 RX、PB2 TX | 当前串口输出通道 |
| 按键 K1～K6 | PB22、PB26、PB16、PB21、PB23、PB24 | 已进入按键任务 |
| 五路循迹 | PA12～PA16 | 已进入 5 ms 采样任务 |
| 外部运行同步 | PB13 | 运行时高，结束时低 |

舵机 PWM、蓝牙和串口屏存在配置或接口，但没有完整业务调用证据。接线表应把它们标成“预留”，不要与“已交付功能”混在一起。

## 4. 已知复用和电气风险

### PA27：蜂鸣器与调参电位器

系统板把 PA27 用于蜂鸣器驱动，扩展板又把它接到 0～5 V 电位器滑动端。两种功能冲突，并且 5 V 可能超过 MCU 输入电源域。高阻输入只能减少输出对顶，不能解决过压。

### PA0：板载 LED 与通信输入

PA0 上存在板载 LED 负载，同时扩展板把它用于通信输入。软件不配置 LED，并不会移除实体电阻和 LED 对波形的影响。启用该串口前需要观察可靠性，必要时处理板载负载。

### PA3/PA4：低频晶振复用

当前硬件记录说明低频晶振未焊接，因此 PA3、PA4 被用于编码器和舵机。这个前提必须跟随硬件版本记录；若后续补焊晶振，相关数字功能必须重新分配。

### 多路供电

调试器、外部 5 V 和板载降压可能形成多个供电入口。上电前先定义唯一主供电路径，测量断电后的反向电压，不把对地保护器件误认为串联隔离器件。

## 5. 分级上电流程

### L0：断电检查

- 核对电源极性、地线与连接器方向；
- 测量主要电源对地阻值，排除明显短路；
- 断开电机、编码器、舵机和非必要模块；
- 确认急停或断电动作能够立即执行。

### L1：仅控制板

接入单一受控电源，测量 5 V、3.3 V 与复位状态。完成 SWD 连接和空工程或当前固件下载，确认 MCU 不异常发热。

### L2：低功率外设

逐个接入 OLED、按键和循迹模块。每增加一项就记录静态电流、总线电平和功能结果，不一次性恢复所有排线。

### L3：编码器

先不接电机驱动输出，手动转动车轮，确认 A/B 信号高电平安全、相位变化存在、正向计数符号一致。此阶段不需要 PID。

### L4：电机架空

接入 TB6612 与电机，车轮悬空。先验证 `STBY`、零 PWM、低指令正反转和停机，再观察供电压降、MCU 复位与编码器反馈。

### L5：低速落地

完成左右轮和编码器的符号核对后，才进行低速直线、定距和循迹。每次只开放一个控制模式，并保留可立即停机的操作员。

## 6. 硬件问题怎样留痕

| 字段 | 记录内容 |
| --- | --- |
| 硬件标识 | 板卡版本、车辆编号、改线说明 |
| 供电 | 电源型号、限流、电压、接入位置 |
| 固件 | 提交号、构建配置、映像校验值 |
| 接线 | 使用的接口、方向、临时飞线 |
| 仪器 | 万用表或示波器型号与量程 |
| 结果 | 数值、波形、照片、复现步骤 |

没有这些上下文，“这块板之前能跑”无法成为可复用的工程证据。

## 本篇总结

- TI 小车同时涉及多个电源域和 3.3 V/5 V 信号边界，接口供电电压不能代替 IO 电平验证。
- 当前双电机由 TIMA0、方向 GPIO 与 TB6612 驱动，双编码器由 TIMG8/TIMG9 QEI 读取；具体连接仍需结合实物版本确认。
- PA27、PA0、PA3/PA4 以及多路供电都存在明确的复用或电气风险，应在接线和版本记录中持续跟踪。
- 上电必须从断电检查逐级推进到控制板、低功率外设、编码器、架空电机和低速落地，不能跳级验证。
