这组资料包含三份相互独立的 C 源码。它们不是同一个可直接编译的工程，而是从基础 PID 到工程增强的三个代码切片。

阅读时应把参数与算法分开：公式可以复用，参数只能作为原作者当时的配置记录。没有采样周期、负载、编码器分辨率和实测曲线，就不能把某组参数称为“最优参数”。

| 资料 | 主要内容 | 证据边界 |
| --- | --- | --- |
| `（位置式）pid.c` | 通用位置式、增量式 PID | 只有实现文件，缺少对应头文件和调用工程 |
| `（低通滤波 增量式）pid.c` | 双电机速度环与一阶低通 | 引用了外部电机、编码器和串口接口 |
| `带前馈、滤波、抗积分饱和的“位置式PID.c` | 位置环、速度环、前馈和条件积分 | 引用了缺失的 `PID.h` 与电机配置宏 |

## `（位置式）pid.c`：两种离散 PID 的基础骨架

### 位置式 PID 的原理

位置式 PID 每次计算完整输出：

```text
e[k] = target - current
u[k] = Kp·e[k] + Ki·Σe[k] + Kd·(e[k] - e[k-1])
```

代码用 `integral` 累加误差，用 `last_error` 保存上一拍误差，再把 P、I、D 三项相加。`pid_out_limit()` 最后将输出限制在 `[-limit, limit]`。

它适合“输出本身具有明确意义”的控制器，例如位置环直接给出目标速度，或速度环直接给出 PWM 指令。

### 增量式 PID 的原理

增量式 PID 先计算本拍相对上一拍的变化量，再累加到原输出：

```text
Δu[k] = Kp·(e[k]-e[k-1])
      + Ki·e[k]
      + Kd·(e[k]-2e[k-1]+e[k-2])

u[k] = u[k-1] + Δu[k]
```

源码中的 `last_error` 和 `last2_error` 正是两拍历史误差。相比位置式，它不会每次从零重新生成输出，常用于连续调节电机速度。

### 代码接口

```c
pid_init(&pid, kp, ki, kd, target, limit);
pid_set_target(&pid, new_target);
output = pid_calculate_positional(&pid, feedback);
output = pid_calculate_incremental(&pid, feedback);
```

`pid_set_target()` 会再次调用 `pid_init()`，因此每次改目标都会同时清空积分、历史误差和当前输出。这适合“切换目标时重新起步”，但不适合需要无扰切换的连续轨迹。

### 使用前必须补齐的条件

基础实现没有把采样周期 `dt` 写进积分和微分公式。因此同一组 `Ki`、`Kd` 只能在固定调用周期下解释；一旦任务周期改变，闭环行为也会改变。

源码虽然提供 `pid_app_limit_integral()`，但它没有在位置式计算中自动调用。只有输出限幅，没有正在工作的积分抗饱和逻辑。

## `（低通滤波 增量式）pid.c`：速度测量先滤波再闭环

这份代码为左右电机各建立一个控制器，并保留独立参数。其控制链可以概括为：

```text
编码器速度 → 一阶低通 → 增量式 PID → 输出限幅 → 左右电机
```

### 一阶低通滤波

代码采用指数平滑：

```c
filtered = alpha * raw + (1.0f - alpha) * filtered;
```

当 `alpha` 较小时，历史值占比更高，曲线更平滑，但相位滞后更明显。速度环会把滞后视作“电机尚未跟上”，因此滤波不能只追求平滑，还要结合控制周期和电机响应调节。

### 双轮独立控制

左右轮分别调用 `pid_calculate_incremental()`，最后通过 `Motor_SetSpeed()` 输出。分开控制是合理的，因为机械装配、减速箱摩擦与电机常数很难完全一致。

```c
left_output  = pid_calculate_incremental(&pid_speed_left, filtered_left);
right_output = pid_calculate_incremental(&pid_speed_right, filtered_right);
```

源码注释把现有参数描述为实调结果，但资料中没有曲线、负载和采样周期记录。文章只确认“代码写入了这些参数”，不把它们当作可迁移的性能结论。

### 集成边界

该文件依赖 `pid_app.h`、编码器对象、电机对象和 `my_printf()`。它不能单独编译，也没有证明与另外两份 `pid.c` 使用同一套 `PID_T` 定义。

目标值旁的 `cm/s` 仅出现在注释中。若编码器模块没有完成“计数到线速度”的标定，就应把它视作控制量，而不是已经确认的物理速度。

## `带前馈、滤波、抗积分饱和的“位置式PID.c`：面向整车的工程增强

这份代码把一个简单控制器拆成位置环和速度环。位置环输出目标速度，速度环再根据编码器反馈输出电机控制量。

```text
目标位置 → 位置环 → 目标 RPM
                      ↓
编码器 RPM → 速度环 + 前馈 → PWM
```

### 前馈与反馈各自做什么

速度环输出由前馈和 PID 反馈组成：

```c
output = Kf * target_rpm
       + Kp * error
       + Ki * integral
       + Kd * derivative;
```

前馈根据目标直接给出基础驱动力，反馈只修正模型误差和外部扰动。这样能减少“全部靠误差堆出 PWM”造成的迟滞，但 `Kf` 仍必须由实际电机、供电和负载标定。

### 测量微分与低通

代码先对实际 RPM 做一阶低通，再对测量值求负微分：

```c
filtered += alpha * (actual - filtered);
derivative = -(filtered - last_filtered) / dt;
```

这属于微分先行。目标值突变时，微分项不会直接产生一次很大的“设定值冲击”；代价是测量噪声与滤波相位仍需共同评估。

### 抗积分饱和

实现包含四层保护：

1. 只有误差进入指定范围时才候选积分。
2. 积分状态本身被限幅。
3. 输出被限制在电机允许范围。
4. 输出饱和时，仅在误差有助于退出饱和的方向上接受新积分。

目标接近零且实际速度落入死区时，代码会清空积分和输出；目标正负方向翻转时，也会重置积分，避免旧方向的累积继续推动车轮。

### 位置环与速度环的职责

`LocationRing_PID_Realize()` 负责把位置误差转换为目标速度，并限制在 `MOTOR_SPEED_MAX`。`SpeedPID_Update()` 再把目标速度转换为受限 PWM。

这种级联结构比“位置误差直接控制 PWM”更容易定位问题：先验证速度环，再接位置环。两个环的运行频率和带宽必须拉开，资料中没有提供实测带宽，仍需上板确认。

## 本篇总结

- 位置式 PID 输出绝对控制量，增量式 PID 输出相对变化量。
- 滤波能降低编码器抖动，但也会引入相位滞后。
- 前馈负责基础驱动力，PID 负责修正模型误差。
- 工程可用的 PID 还需要固定周期、限幅、死区、状态重置和抗积分饱和。
- 参数必须通过真实车辆的阶跃曲线和负载条件重新标定，不能从示例源码直接复制。
