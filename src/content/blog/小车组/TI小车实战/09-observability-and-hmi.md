一辆车能跑，不等于它可维护。新成员必须知道系统处于什么模式、目标是什么、反馈是否可信、为什么停止。可观测性就是把内部状态转换为低成本、可追溯的外部证据。

| 文档属性 | 内容 |
| --- | --- |
| 文档编号 | TI-CAR-09 |
| 交互入口 | 六个按键 |
| 本地反馈 | OLED、LED、蜂鸣器 |
| 数据反馈 | UART 调试序列、PB13 外部运行信号 |

## 1. 交互不是直接改变量

按键任务每 20 ms 读取一次输入，并用连续样本做消抖。根据当前编译配置，按键会启动 20 秒循迹、双轮定距、30 秒循迹、参数步进或外部同步信号测试。

按键语义依赖 `STRAIGHT_DEBUG_ENABLE` 与 `TRACK_DEBUG_KEY_CONTROL_ENABLE`。因此面板标签、文档和发布记录必须与实际宏配置一致，不能只写“按 K1 启动”而不说明固件版本。

有效按键动作会先检查当前运动状态。部分按键在运动中触发统一停止，而不是启动第二个任务。这可以避免两个模式同时争用速度目标。

## 2. OLED 是状态摘要

OLED 初始化成功后才会登记刷新任务。当前主要页面能显示：

- 20 秒或 30 秒配置；
- `ACC`、`RUN`、`DEC`、`WAIT` 等阶段；
- 左右累计距离与目标距离；
- 左右实际 RPM；
- 左右目标 RPM；
- 直线定距模式下的目标、实际和完成状态。

OLED 适合现场快速判断，不适合保存完整时间序列。页面应优先展示状态、目标和异常，而不是堆叠所有调试变量。

## 3. 串口是分析通道

当前循迹模式下，串口按约 50 ms 周期输出十个字段：

| 序号 | 字段 |
| ---: | --- |
| 1 | 原始循迹偏差 |
| 2 | 滤波循迹偏差 |
| 3 | 偏差变化率 |
| 4 | 转向修正 RPM |
| 5 | 左目标 RPM |
| 6 | 左滤波实际 RPM |
| 7 | 左 PWM |
| 8 | 右目标 RPM |
| 9 | 右滤波实际 RPM |
| 10 | 右 PWM |

接收端应把字段表与固件版本一起保存。无表头的十列数字若脱离版本，后续很难判断列含义是否改变。

当前 `MyPrintf()` 使用逐字节阻塞发送。虽然串口任务频率低于控制任务，日志量仍必须受控；增加字段或提高频率前，应测量发送耗时对 10 ms 控制周期的影响。

## 4. LED、蜂鸣器和外部同步

### LED

LED 每 100 ms 翻转，可作为主循环仍在调度的粗粒度心跳。它不能证明 PID 周期准确，也不能证明所有任务健康。

### 蜂鸣器

蜂鸣器由 10 ms 周期状态机产生短脉冲，不使用长阻塞延时。按键确认和任务完成可用不同脉冲次数表达，但应保持语义稳定。

### PB13 外部运行信号

任务开始时可将 PB13 拉高，停止收口时拉低。它适合让外部设备记录任务窗口。K6 还提供不启动电机的模拟运行测试，可在联调外部设备时降低风险。

## 5. 建立统一状态词典

建议把显示、日志和测试报告统一为以下状态：

| 状态 | 含义 | 允许输出 |
| --- | --- | --- |
| IDLE | 已初始化、无运动任务 | PWM 零，外部同步低 |
| ACC | 目标斜坡上升 | 速度闭环与循迹有效 |
| RUN | 稳态任务执行 | 持续记录目标和反馈 |
| DEC | 接近距离目标 | 基础速度受剩余距离限制 |
| WAIT | 等待终点图案 | 低速循迹与模式确认 |
| STOP | 正常停车过程 | 目标向零收敛 |
| DONE | 已达到任务完成条件 | 输出收口、提示完成 |
| FAULT | 检测到不可继续条件 | 禁止自动重新启动 |

当前代码尚未形成统一 `FAULT` 管理器。新增传感器超时、电源异常或通信故障时，建议把故障码、首次发生时间和恢复策略作为独立模块设计，而不是只在 OLED 打印一句错误。

## 6. 一条可诊断日志应包含什么

控制数据之外，企业化日志还应包含：

- 固件版本或提交号；
- 车辆与硬件编号；
- 运行配置与关键参数版本；
- 任务开始、阶段切换、停止原因；
- Tick 或相对时间；
- 异常码和首次发生上下文。

数据频率要分层：高速控制量用于短时分析，低频状态用于长时记录，事件日志只在状态变化时输出。所有信息都以 50 ms 文本持续刷屏，会浪费带宽并掩盖关键事件。

## 7. 可观测性测试

| 操作 | 期望外部证据 |
| --- | --- |
| 上电不启动 | IDLE、PWM 零、PB13 低 |
| 启动任务 | 按键提示、PB13 高、状态进入 ACC |
| 进入巡航 | OLED/RUN 与串口目标稳定 |
| 接近目标 | 状态进入 DEC，目标 RPM 下降 |
| 正常完成 | 速度归零、PB13 低、完成蜂鸣 |
| 运行中中止 | 模式清空、PWM 零、外部同步低 |
| OLED 断开 | 控制仍运行，OLED 任务不登记或失败可识别 |

最后一项用于验证降级能力：显示设备失效不应直接使控制链崩溃，但必须让维护者能够知道显示初始化没有成功。

## 8. 信息化交付建议

每次重要路测生成一个测试编号，把固件提交、车辆编号、参数快照、串口 CSV、现场视频和结论关联起来。参数调整不要只留在聊天记录或口头说明中。

对比两次测试时，应以相同路线、负载、电量区间和采样字段为前提。否则曲线变化可能来自环境，而不是代码改进。

## 本篇总结

- 按键负责受控地触发模式，OLED 提供现场摘要，串口提供时间序列，LED、蜂鸣器和 PB13 提供轻量状态信号。
- 当前按键语义受编译宏影响，发布文档必须与实际固件配置绑定。
- 阻塞式串口输出可能影响合作式调度，扩展日志前要测量执行时间并分层控制频率。
- 可维护系统还需要版本、参数、阶段、停止原因和故障上下文，而不只是若干实时数值。
