# 常见嵌入式工具链证据入口

以下文件只能作为调查入口，不能单凭文件存在就断言它属于当前活动构建。

## TI Code Composer Studio

- `.project`、`.cproject`：工程、构建配置、编译器和包含路径。
- `.syscfg`：SysConfig 外设、引脚和时钟配置；确认生成文件是否参与活动配置。
- `.cmd`：链接脚本、存储区和段布局。
- `Debug/`、`Release/`：通常是生成物；除非为诊断构建问题，不要把它们当作源码真相源。
- 从 `main`、板级初始化、SysConfig 生成入口追踪到项目逻辑；区分 SDK 示例代码和自研代码。

## STM32CubeIDE / STM32CubeMX

- `.ioc`：器件、引脚、时钟和中间件配置入口。
- 启动文件与 `.ld`：中断向量、内存区域和段布局。
- HAL/LL 配置头：已编译模块线索，仍需检查实际初始化与调用。
- 保护 `USER CODE` 区域边界；生成代码不等于作者手写逻辑。

## Keil MDK

- `.uvprojx`：目标、器件、源文件组、宏、包含路径和构建选项。
- startup 文件、scatter 文件：启动与内存布局。
- RTE/Pack 配置：中间件和设备包线索；记录包版本。
- 多 Target 工程必须先确认当前目标，不能混合引用不同目标的配置。

## PlatformIO

- `platformio.ini`：环境、平台、板卡、框架、构建宏和库依赖。
- 多个 `[env:*]` 时先确定目标环境。
- `.pio/` 是生成目录，不作为主要文档来源。

## CMake / Make

- `CMakeLists.txt`、工具链文件、`Makefile`：源文件集合、宏、编译选项和目标。
- 链接脚本、启动文件、生成命令：内存和启动事实。
- 仅被条件分支引用的源文件要结合实际构建参数判断。

## 通用调查顺序

1. 找活动目标、器件和构建配置。
2. 确定真正参与编译和链接的源文件。
3. 找复位入口、`main`、RTOS 启动或调度入口。
4. 追踪外设初始化到业务调用。
5. 对照原理图/板卡资料验证引脚、电平和供电。
6. 用日志、波形或演示记录确认运行行为。
