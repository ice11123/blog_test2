# ADR 0001：浏览器运行时与状态边界

- 状态：已接受
- 日期：2026-09-02

## 背景

本站使用 Astro ClientRouter。公共数据、图表、主页手势和管理台均包含浏览器运行时状态；这些脚本在首次载入后可能跨多次页面切换继续存在。若 Module 只在顶层捕获 DOM，或把网络失败压缩成单一布尔状态，会造成旧节点泄漏、返回页面失效和错误状态误报。

## 决策

1. 路由相关 Module 必须提供可重复调用的挂载与释放边界。`astro:page-load` 只挂载当前文档需要的 Implementation，`astro:before-swap` 释放监听器、观察器、定时器、动画、请求和旧 DOM 引用。
2. 外部资源加载通过统一 Adapter 管理。加载状态至少区分 idle、loading、loaded 和 failed；失败或超时后必须淘汰无效脚本，允许下一次调用重新加载。
3. 公共数据请求通过统一 Interface 管理并发、超时、取消和错误分类。页面 Module 不自行实现无限等待；缓存必须携带版本、时效和完整性信息。
4. 部署状态区分 `success`、`pending`、`failure`、`unavailable` 和 `unknown`。只有上游明确返回失败结论时才能使用 `failure`。
5. 管理台本地草稿写入必须可验证。持久化失败不得显示成功；编辑中的内存内容不得因存储异常被覆盖。
6. `CLOUD_PUBLISH_ENABLED=false` 只表示 OAuth/GitHub 写入关闭，不否定只读 Worker 健康与公共状态接口已经部署。管理界面必须使用准确措辞区分两者。

## 结果

这些约束形成稳定的 Seam：页面组件只依赖小而明确的 Interface，网络、存储和第三方脚本细节留在更深的 Module 内。测试应优先验证这些接口和跨路由行为，而不是依赖具体源码文本。

## 非目标

- 不因性能优化删除三层波浪、壁纸抽屉、主题圆形过渡或其他既有视觉效果。
- 本决策不启用云发布，也不授权部署 Worker。
- 外部输入攻击面和依赖安全升级由独立安全工作处理。
