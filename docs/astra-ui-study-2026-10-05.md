# Astra：blog2 与 astro-koharu 视觉、互动体验对照

审查日期：2026-10-05。本文是只读审查结果，不是实施记录或任务状态来源；任务状态由 Beads `blog_test2-lh3` 管理。

后续实施与验收另见 [视觉反馈与阅读交互实施记录](ui-reading-implementation-2026-10-05.md)，由 Beads `blog_test2-glr` 追踪。下文保留原始审查时点，不将建议和实施事实混写。

## 结论

blog2 目前更需要建立一致的视觉与互动语言，而不是继续增加装饰效果。参考站的优势是把身份、内容入口、阅读位置和操作反馈串成连续体验；不能把这种优势简单归因于框架、托管平台或动画数量。

保留本站已有的三层波浪、壁纸抽屉、左右侧栏、主题圆形切换、技术星图与软件展示。借鉴的是设计原则，不进行逐像素复制，也不搬入参考仓库的 AGPL-3.0 源码。

## 核心诊断：不是不够华丽，而是几种语言混在一起

### 1. 首页要分清作品、知识入口和运行信息

本站技术星图和 Click-Clean 卡片已经有自己的识别度，不应换成参考站同款图片文章卡。问题是不同模块缺少主次：知识分类用大标题和立体素材，近期更新用文档编号，运行状态又像管理控制台。

建议将首页组织为三个连续层级：知识入口、最近更新与作品、站点维护信息。保留每个现有模块与内容，但用同级标题节奏、留白和背景层明确区分读者内容与运行信息。运行状态不是普通访客的主要任务，不应与正文入口使用相同视觉权重。

近期文章已按系列聚合，卡片标题实际可能是系列名；建议栏目语义改为“近期更新”，并明确“系列入口”和“完整目录”各自目的地。不能为了统一卡片外观，把学习笔记恢复成最新发布优先的目录排序。

### 2. 装饰与信息需要不同的空间契约

技术星图当前 `.topic-copy` 占比与 `.topic-art` 占比会重叠；电控图片还放大到装饰区域的 142%，并带旋转和正向 Z 位移。静态看起来丰富，不代表文字区域在所有断点、悬停状态都安全。

建议把可读内容作为平面信息层，把立体素材置于单独的 3D 舞台。素材可以移出自身背景轮廓，但不能侵入可点击文字。默认、悬停、按压、焦点四种状态都必须满足这一条。不能通过隐藏日期、删除近期链接或整体降低图片透明度来掩盖冲突。

### 3. 左右栏需要职责清晰，不是统一塞进一处

用户已明确要求左栏为个人／目录／标签、文章目录单独在最右侧，继续保留。

参考站文章左栏是概览／本文目录／系列文章，不能直接替换本站结构。值得借鉴的是当前状态醒目、面板衔接轻量、阅读位置清楚。本站更适合“左侧找文章，右侧找章节”的固定职责，名称和活动状态必须对应。

标签 151 项不是视觉样式能独自解决的规模问题。过滤、完整名称和清晰排序比把按钮做得更小更精致更有效；完整列表仍保留。

### 4. 阅读场景需要专门设计

本站当前文章文件 50 个，包含长系列、公式和工程图片。参考站本轮首页列出 4 篇文章，不能沿用用户早期截图的 2 篇数量，也不能直接把短文页面当作本站所有阅读场景的尺寸模板。

在 1100px 宽度，按当前源码计算：左右栏共 430px，中间约 670px，扣除文章外边距与正文内边距后，正文约 482px。这只是源码估算，实施验收应读取真实布局。它提示需要关注中等桌面断点，而不只检查 1440px 和手机。

不建议立即隐藏用户要求常驻的左栏。先重新分配中等桌面下的侧栏宽度和正文内边距；完整标题、公式自身横向滚动、文章无横向溢出必须同时满足。

图片查看器与连续章节导航的价值高于再加一层卡片动画。对于笔记，必须保持原 Markdown 文本、公式、颜色语义、图片资源和顺序；所有增强放在外层交互，不改笔记正文。

## 不应照搬的参考实现

- 参考 `segmented.tsx` 会动画 `max-width`、`margin`；借鉴选中态突出，但实现用固定几何、合成层指示器，避免标签伸缩把周围布局推来推去。
- 参考 `Navigator.tsx` 的下划线包含 `transition-all` 和宽度变化；本站已有 `scaleX`，没有必要退回布局属性动画。
- 参考 `SearchDialog.tsx` 有 150ms 聚焦等待；本站现在立即聚焦且保护中文输入法，不应为了视觉一致重新引入等待。
- 参考卡片图片有 500ms 放大／旋转，部分工具使用 `transition-all`；其视觉气质可以借鉴，不等于这些参数适合本站。
- Astra 在参考移动文章截图中观察到右侧工具栏压在代码内容旁；本站不应新增四个常驻悬浮按钮占用同样空间。
- 参考主题使用 React islands、Motion、Nanostores、Floating UI；本站现有 Astro、原生 DOM、WAAPI 足以实现以上建议，增加整套依赖并不能保证更好体验。

## 建议实施顺序与验收标准

此处是审查建议，尚未创建实施任务或作出发布承诺。

### 第一阶段：先修明确的视觉和语义问题

范围：星图文字安全区；全站目录／本文目录命名；标签完整可读；卡片主、次入口独立反馈。

验收：1440、1100、1024、390、320px，亮暗主题的默认与悬停状态中，装饰不遮挡文字；标签名称可以完整识别；键盘焦点与鼠标反馈对应相同目的地；不改变页面路由、分类、正文、文章顺序和现有动画效果。

### 第二阶段：补阅读互动闭环

范围：文章专用移动阅读入口、当前章节／进度、正文图片查看、系列上一篇／下一篇、搜索状态。

验收：当前章节复用 TOC 状态，不新增第二套滚动扫描；顶栏位置稳定；侧边箭头仍能使用；图片放大关闭后恢复阅读位置和焦点；搜索加载／失败有明确反馈；原笔记内容和颜色逐项保持；新增功能在首次使用前不加载重型运行时。

### 第三阶段：统一视觉与动效系统

范围：surface／elevation、标题节奏、侧栏活动底板与面板衔接、长目录展开执行路径。

建议的小反馈参数为按压 100–160ms、指针面板衔接 150–180ms；复用现有 `--ease-out` 与 `--ease-drawer`。这些只是候选值，不擅自覆盖现有壁纸、波浪和主题参数。

验收：连续快速反向操作无跳端点、闪图、焦点丢失；键盘高频操作立即响应；降低动态模式正确；在同一浏览器、同一视口、同一操作下比较帧时间和长任务，不能仅凭主观“丝滑”验收，也不能用删除效果达标。

## 动效审查 Verdict

**Block：不建议在现有信息边界上继续堆动画。**

- 视觉与操作含义：先解决装饰／信息冲突、左右目录同名、长标签无法辨识。
- 性能：主目录真实 `height` 动画需要单独测量并优化，不能将 WAAPI 当作自动合成保证。
- 连贯性：近期卡片子入口和侧栏活动状态需要一致反馈；搜索加载／失败需要显式状态。
- 不作未经测量的结论：没有证据证明参考站所有动画无掉帧，也没有证据证明本站卡顿来自 GitHub Pages 上限。
